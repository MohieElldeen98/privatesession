# تطبيق إدارة جلسات العلاج الطبيعي المنزلي

تطبيق ويب بسيط وسريع لمستخدم واحد (أخصائي علاج طبيعي) لإدارة المرضى والجلسات والتحصيل من الهاتف.

**التقنيات:** Next.js 14 (App Router) · TypeScript · Tailwind CSS · shadcn/ui · Supabase
**التصميم:** Mobile First · عربي RTL · واجهة عملية نظيفة.

---

## المميزات

- شاشة رئيسية = جلسات اليوم + ملخص سريع (مرضى نشطون / جلسات اليوم / إجمالي المستحقات).
- لكل جلسة اليوم: اتصال · واتساب · فتح ملف المريض.
- إضافة مريض → توليد 12 جلسة تلقائيًا حسب تاريخ البداية ونظام الأيام.
- ملف المريض: بيانات + الحالة المالية + تسجيل دفعة + جدول الجلسات (تعديل الحالة والوقت والملاحظة).
- نظام تحصيل ذكي حسب طريقة الدفع (مقدم / جلسة بجلسة / مؤخر كل 3 جلسات مع تنبيه بالمستحق).
- بحث بالاسم/الهاتف/المنطقة + ترتيب حسب الاسم أو المنطقة + أرشيف للكورسات المنتهية.

## خطوات الربط بـ Supabase (خطوة بخطوة)

### 1) أنشئ مشروع Supabase
- ادخل على https://supabase.com → New Project.
- اختر اسمًا وكلمة مرور لقاعدة البيانات وانتظر التهيئة.

### 2) أنشئ الجداول
- من القائمة الجانبية: **SQL Editor** → **New query**.
- **قاعدة بيانات جديدة:** انسخ محتوى `supabase/schema.sql` بالكامل والصقه ثم **Run**.
- **عندك بيانات بالفعل من نسخة قديمة؟** شغّل ملفات الترقية بالترتيب مرة واحدة لكل ملف: `supabase/migration.sql` ثم `supabase/migration2.sql` — بيضيفوا الأعمدة الجديدة (الميعاد، رقم الكورس، الحقول الطبية، ملفات المريض، ومخزن الملفات) من غير ما تفقد بياناتك.
- (اختياري) لتجربة بيانات جاهزة على قاعدة جديدة: شغّل `supabase/seed.sql`.

### 3) احصل على المفاتيح
- من **Project Settings → API**:
  - `Project URL` → ضعه في `NEXT_PUBLIC_SUPABASE_URL`.
  - `service_role` (تحت Project API keys) → ضعه في `SUPABASE_SERVICE_ROLE_KEY`.

> ⚠️ مفتاح `service_role` سرّي ويُستخدم على السيرفر فقط (داخل Server Actions/Server Components). لا تضعه أبدًا في كود يعمل على المتصفح.

### 4) أعدّ ملف البيئة
- انسخ `.env.local.example` إلى `.env.local` واملأ القيمتين:

```
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
SUPABASE_SERVICE_ROLE_KEY=your-service-role-key
```

### 5) شغّل التطبيق محليًا

```bash
npm install
npm run dev
```

ثم افتح http://localhost:3000

### 6) النشر (اختياري)
- ارفع المشروع على Vercel، وأضف نفس متغيري البيئة في إعدادات المشروع، ثم Deploy.

## ملاحظات على بعض القرارات

- **بيانات المريض:** السن، العنوان التفصيلي (تحت المنطقة)، التشخيص، Present/Past history، وقوائم اختيار (الأعراض، العمليات، برنامج العلاج) تقدر تضيف عليها أي بند جديد.
- **الملفات والأشعة:** ترفع صور/PDF لكل مريض (مخزن خاص، الوصول عبر روابط موقّعة من السيرفر). الحد 10 ميجا للملف.
- **تعديل/حذف المريض:** زر تعديل بيفتح نفس الفورم مملوءًا، وزر حذف بيشيل المريض وكل جلساته ودفعاته وملفاته (بعد تأكيد).
- **الحاسبة:** بتحسب بسعر الجلسة بعد الخصم، وتقدر تضيف أكتر من مريض بعدد جلسات مختلف ويجمعهم. وإيرادات الفترة (أسبوع/شهر/مخصّص) بتجمع كل الجلسات الفعلية بغضّ النظر عن الدفع.
- **تحديد متعدد للجلسات:** زر «تحديد متعدد» بيخليك تعلّم على كذا جلسة وتغيّر حالتهم مرة واحدة.
- **الكورسات:** كل كورس قابل للطي/الفتح، وتحت رقمه مكتوب الإجمالي التراكمي (كورس 2 = إجمالي 24 جلسة). والتجديد بيخليك تحدد تاريخ بداية الكورس الجديد فيظبط الأيام تلقائيًا.
- **التحصيل بضغطة:** في صفحة المريض زر سريع يسجّل المبلغ المناسب حسب طريقة الدفع (المقدم كامل / دفعة جلسة / المستحق الآن)، وزر تاني لمبلغ مختلف.
- **تبويب الحساب:** بيحسب إيراد أي فترة (أسبوع/شهر/مدة مخصّصة) كمجموع أسعار الجلسات الفعلية فيها بغضّ النظر عن طريقة الدفع، مع تفصيل لكل مريض، بالإضافة لحاسبة (مريض × عدد جلسات). الحساب بسعر الجلسة قبل أي خصم.
- **تأجيل جلسة:** لما تأجّل جلسة، النظام بيضيف تلقائيًا جلسة تعويضية في آخر نفس الكورس عشان يفضل العدد 12 جلسة فعلية. ولو رجّعت حالتها بيشيل التعويضية.
- **تجديد الكورس:** زر «تجديد» بيضيف كورس جديد بـ 12 جلسة بعد آخر جلسة، والجدول بيتقسم «كورس رقم 1»، «كورس رقم 2»... مع إجمالي جلسات كل كورس.
- **وقت الجلسة:** يُولَّد فارغًا ويظهر كـ «—»، ويمكن ضبطه عند فتح الجلسة (مع الحالة والملاحظة) ليظهر مرتبًا في شاشة جلسات اليوم.
- **الخصم:** يُخصم كمبلغ إجمالي من إجمالي الكورس (سعر الجلسة × 12 − الخصم).
- **مؤخر كل 3 جلسات:** المستحق = (عدد الجلسات المكتملة مقربًا لأقرب 3) × سعر الجلسة الفعلي − المدفوع، ويظهر تنبيه عند وجود مستحق.
- **الأمان:** التطبيق لمستخدم واحد بلا تسجيل دخول (حسب المطلوب). الوصول للبيانات يتم من السيرفر فقط عبر مفتاح الخدمة، وRLS مفعّل بدون أي Policy عامة فلا وصول من المتصفح مباشرة. للحماية الإضافية، احتفظ برابط التطبيق خاصًا.

## بنية المشروع

```
supabase/
  schema.sql        # إنشاء الجداول والفهارس و RLS
  seed.sql          # بيانات تجريبية
src/
  app/
    page.tsx                 # الرئيسية: جلسات اليوم + الملخص
    patients/page.tsx        # قائمة المرضى + بحث + أرشيف
    patients/new/page.tsx    # إضافة مريض
    patients/[id]/page.tsx   # ملف المريض
    actions/                 # Server Actions (CRUD)
  components/                # مكونات الواجهة + shadcn/ui
  lib/                       # الأنواع، الحسابات، التحقق، عميل Supabase
```
